After a rider signs in, the app stores the session in `sessionStorage` under the key `cm_tp_session`. Every part of the app that needs to know who is signed in — the header chip, the navigation drawer, the account page, API calls — reads session state through two exported functions: `getSession()` and `getAccessToken()`. Sign-out is available in two forms: a local-only variant and a global variant that terminates the session at the provider as well. All of these operations are coordinated through the `cm-auth` custom DOM event, which triggers a UI re-render whenever authentication state changes.

---

## Reading the Session

### getSession()

`getSession()` is the authoritative way to check whether a rider is signed in. It reads `cm_tp_session` from `sessionStorage`, checks the `expiresAt` timestamp, and either returns the session object or cleans up the stale entry.

```js title="js/oauth.js — getSession"
export function getSession(e) {
  const env = withEnv(e);
  let s = null;
  try { s = JSON.parse(env.storage.getItem(KEYS.session)); } catch { /* none */ }
  if (!s) return null;
  if (!(s.expiresAt > env.now())) {
    env.storage.removeItem(KEYS.session);
    setNotice('session_expired', 'Your session ended. Sign in again to continue.', env);
    return null;
  }
  return s;
}
```

When `expiresAt <= Date.now()`, `getSession()`:
1. Removes the stale `cm_tp_session` entry from `sessionStorage`.
2. Writes a `session_expired` notice to `cm_tp_notice`.
3. Returns `null`.

The next time the rider navigates to the sign-in screen, `takeNotice()` reads and clears that notice, and the screen displays the message **"Your session ended. Sign in again to continue."**

<ResponseField name="return value" type="Session | null">
  Returns the full session object if a valid, unexpired session exists. Returns `null` if no session is present or the session has expired.
</ResponseField>

### getAccessToken()

A convenience wrapper that extracts just the Bearer token from the session. Use this when making authenticated API requests on behalf of the rider.

```js title="js/oauth.js — getAccessToken"
export const getAccessToken = e => {
  const s = getSession(e);
  return s ? s.accessToken : null;
};
```

Returns `null` (not a thrown error) if there is no valid session, so callers can check for `null` and redirect to `#/signin` without a try/catch.

## Session Lifetime

Sessions are **tab-scoped**: `sessionStorage` is cleared automatically when the rider closes the browser tab. There is no persistent login across sessions.

Within a tab, the `expiresAt` value controls lifetime:

<Accordion title="How expiresAt is calculated">
  During `completeLogin()`, `expiresAt` is derived from the token response:

  ```js title="js/oauth.js — expiresAt calculation"
  expiresAt: env.now() + (
    tok.expires_in
      ? tok.expires_in * 1000
      : Math.max(0, id.exp * 1000 - env.now())
  )
  ```

  - **Primary source:** `expires_in` from the token response (in seconds), converted to milliseconds and added to the current time.
  - **Fallback:** If `expires_in` is absent, the `exp` claim from the decoded ID token is used directly — `Math.max(0, id.exp * 1000 - Date.now())` gives the remaining milliseconds.

  Once `expiresAt` is reached, `getSession()` treats the session as gone and removes it on the next access.
</Accordion>

## Sign-Out

Trip-Planner offers two distinct sign-out operations with different scopes of effect.

<Note>
  **Local sign-out** (`signOut`) ends the rider's session in this browser tab only. Their City Metro transit account remains signed in at the provider, and other City Metro apps (Alerts, BrickPass, etc.) are unaffected. **Global sign-out** (`signOutEverywhere`) additionally ends the provider session, which may sign the rider out of all City Metro services simultaneously — depending on how each service handles session state.
</Note>

<Tabs>
  <Tab title="Local sign-out">
    `signOut()` clears only the two auth keys from `sessionStorage`. It is synchronous and does not make any network request. The rider's City Metro account at `auth.citymetro.xyz` remains active.

    ```js title="js/oauth.js — signOut"
    // Signs out of THIS app only. The City Metro transit account itself stays
    // signed in at the provider.
    export function signOut(e) {
      const env = withEnv(e);
      env.storage.removeItem(KEYS.session);  // 'cm_tp_session'
      env.storage.removeItem(KEYS.flow);     // 'cm_tp_oauth'
    }
    ```

    **Usage in the account view:**

    ```js title="js/account.js — local sign-out handler"
    $('#signOutBtn').addEventListener('click', () => {
      signOut();
      notifyAuthChange();
      toast('You signed out of Trip-Planner.');
      navigate('/');
    });
    ```

    After `signOut()`, `notifyAuthChange()` fires the `cm-auth` event so the header chip and drawer re-render immediately.
  </Tab>

  <Tab title="Global sign-out">
    `signOutEverywhere()` is async. It discovers the provider's `end_session_endpoint`, builds a logout URL with `id_token_hint` and (optionally) `post_logout_redirect_uri`, clears the local session, and returns the URL for the caller to navigate to.

    ```js title="js/oauth.js — signOutEverywhere"
    // Returns the URL to send the browser to, or null if the provider has none.
    // Local session is cleared either way.
    export async function signOutEverywhere(e) {
      const env = withEnv(e), session = getSession(env);
      let url = null;
      try {
        const meta = await discover(env);
        if (meta.end_session_endpoint) {
          const u = new URL(meta.end_session_endpoint);
          if (session && session.idToken)
            u.searchParams.set('id_token_hint', session.idToken);
          if (env.config.postLogoutRedirectUri)
            u.searchParams.set('post_logout_redirect_uri', env.config.postLogoutRedirectUri);
          url = u.toString();
        }
      } catch { /* offline or unconfigured: fall back to local sign-out */ }
      signOut(env);
      return url;
    }
    ```

    **Return value:** `Promise<string | null>`
    - Returns a fully-formed logout URL if the provider exposes `end_session_endpoint`.
    - Returns `null` if discovery fails or the provider has no end-session endpoint.
    - In either case, the local session is cleared before the promise resolves.

    **Usage in the account view:**

    ```js title="js/account.js — global sign-out handler"
    $('#signOutAll').addEventListener('click', async e => {
      const url = await signOutEverywhere();
      notifyAuthChange();
      if (url) location.assign(url);   // send to provider logout page
      else navigate('/');              // fall back to local-only result
    });
    ```
  </Tab>
</Tabs>

## The cm-auth Custom Event

Any component that renders auth-dependent UI must react to sign-in and sign-out events without polling. The `cm-auth` custom DOM event handles this — it is dispatched on `window` by `notifyAuthChange()` after every state change.

```js title="js/shell.js — event definition and subscription"
// Subscribe: re-render the header chip and navigation drawer on any auth change.
addEventListener('cm-auth', () => {
  renderAccountChip();
  renderDrawer();
});

// Dispatch: call this after every sign-in or sign-out.
export const notifyAuthChange = () => dispatchEvent(new Event('cm-auth'));
```

`notifyAuthChange()` is called in three places:

| Location | Trigger |
|----------|---------|
| `js/account.js` | After `signOut()` — rider taps "Sign out of Trip-Planner" |
| `js/account.js` | After `signOutEverywhere()` — rider taps "Sign out of all City Metro services" |
| `js/shell.js` | After `signOut()` in the navigation drawer sign-out handler |

The shell's `cm-auth` listener re-renders both the **account chip** in the header (shows the rider's name and avatar when signed in, a "Sign in" prompt when not) and the **navigation drawer** (which includes the sign-out button only when a session exists).

## One-Time Notices

Notices allow a short message to survive a redirect — from `callback.html` back to `#/signin` after a failed sign-in, or from any page that detects an expired session.

```js title="js/oauth.js — setNotice and takeNotice"
// Write a notice (cross-navigation, one-time).
export function setNotice(code, message, e) {
  withEnv(e).storage.setItem(KEYS.notice, JSON.stringify({ code, message }));
}

// Read and immediately delete the notice (single-use).
export function takeNotice(e) {
  const env = withEnv(e);
  try {
    return JSON.parse(env.storage.getItem(KEYS.notice));
  } catch {
    return null;
  } finally {
    env.storage.removeItem(KEYS.notice);
  }
}
```

`takeNotice()` uses a `finally` block to ensure the notice is removed even if JSON parsing throws — no notice is ever shown twice.

<Accordion title="Notice codes used by the auth module">

| Code | Set by | Message shown on sign-in screen |
|------|--------|----------------------------------|
| `session_expired` | `getSession()` — on expiry detection | "Your session ended. Sign in again to continue." |
| `cancelled` | `completeLogin()` — on `access_denied` from provider | "Sign-in was cancelled. You were not signed in." |
| `state_mismatch` | `completeLogin()` — on CSRF check failure | "We couldn't verify that sign-in came from this device. Please start again." |
| `flow_expired` | `completeLogin()` — on 10-minute timeout | "That sign-in took too long. Please start again." |
| `token_failed` | `completeLogin()` — on network error at token endpoint | "We couldn't reach the sign-in service to finish signing you in." |
| `id_token_invalid` | `completeLogin()` — on claim validation failure | "The sign-in response could not be verified. Please try again." |

</Accordion>

The sign-in screen distinguishes between **gentle** notices (displayed as an informational banner) and **error** notices (displayed as an error banner) using a hard-coded set:

```js title="js/signin.js — notice severity"
const GOOD = new Set(['cancelled', 'session_expired']);  // info banner
// all other codes → error banner
```
